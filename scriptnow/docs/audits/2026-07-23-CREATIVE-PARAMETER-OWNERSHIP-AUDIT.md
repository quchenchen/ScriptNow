# 创作参数归属与硬编码审计

## 结论

创作链路采用三类所有权，不允许互相越界：

1. **用户所有**：媒介、来源、类型、语言、叙事结构、剧本格式、卷/篇章/场数、单章目标词数、单场目标时长、世界规则、风格边界。
2. **Agent 所有**：创意候选、人物与世界语义、蓝图锚点、章节/场景标题、节拍内容、正文、审读意见、包装文案与封面提示词。
3. **系统所有**：鉴权、租户隔离、幂等、版本、超时、重试、上下文大小、安全限额、候选状态机和结构校验。

用户参数必须由前端显式选择并持久化；Agent 可以建议修改，但不能静默覆盖。系统只校验边界，不能补写故事。

## 已发现并修复

| 链路 | 原问题 | 修复 |
|---|---|---|
| 小说 StoryMap | 固定十二章标题与固定目标词数 | 由故事建筑师 Agent 生成语义；卷数、每卷章数、每章词数读取项目设置并强校验 |
| 剧本创意发散 | 三个固定故事方向污染所有项目 | 改为创意总监 Agent 根据项目参数与用户反馈生成 |
| 剧本蓝图 | 固定城市、档案管理员、未来邮戳信件 | 改为故事建筑师 Agent 根据已采纳方向生成 |
| 剧本 StoryMap | 固定一篇两场、120/150 秒 | Agent 生成标题与节拍；篇章数、每篇场数、单场分钟数读取前端设置 |
| 创建向导 | 预选三幕结构、1 卷/8 章/2 分钟等业务默认 | 取消预选；未明确填写不能进入确认步骤 |
| 自定义结构 | 只有“自定义”枚举，没有实际规则输入 | 增加自定义结构文本，并作为项目结构参数传入 Agent |
| 回归保护 | 示例故事可能再次进入生产代码 | 新增生产目录禁用示例故事内容及禁止体量预选的测试 |

## 保留的常量

以下不是创作硬编码，继续保留在系统或领域契约中：

- JWT、Cookie、上传大小、API 字段长度、请求超时、循环上限；
- 候选状态、版本号、幂等键、租户隔离；
- “恰好三个创意候选”等产品交互契约；
- 蓝图覆盖类别、审读维度等质量契约。

这些常量后续若需要运营调节，应进入管理后台的版本化策略配置，而不是由普通创作前端逐项暴露。

## 尚待产品化的策略配置

- 创意候选数量目前仍是产品契约 3；
- 蓝图最低覆盖类别与锚点数量仍是领域质量契约；
- Agent 最大循环次数、RAG 轮数和各阶段 token 上限属于运行策略；
- 支持在管理后台建立“策略版本”，但不得与单个作品的创作参数混在一起。
