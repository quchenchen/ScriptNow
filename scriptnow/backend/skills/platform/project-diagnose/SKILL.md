# Diagnose project state

1. Read only the project facts exposed by domain tools; never infer missing canon from chat history.
2. Check the current phase, accepted candidates, unresolved review findings, continuity constraints, and target deliverable.
3. Classify each problem as blocking, degradable, or informational.
4. If facts conflict, cite both records and request a decision through a candidate; never silently rewrite truth.
5. Return a compact readiness result: `ready`, `blocked`, or `ready_with_risks`, followed by evidence and the next valid action.
6. Do not mutate project truth. All proposed changes must use the domain candidate workflow.
