## 1. 结论

V7 已能持久化并展示一部接近 2 万字的真实小说，从创意候选、蓝图、StoryMap、逐章正文、审读、修订、快照一直走到 DOCX 导出；候选与采纳事实的边界在本次流程中成立，刷新与断点恢复后数据没有丢失。

但这次通过的是“真实内容进入真实领域工作流”，不是“Agent 自主生成长篇小说”。当前 Mock Runtime 只能产出模板短文，因此十五章正文由真实创作样稿提供，再通过新增的候选提案接口逐步进入系统。自动创作、语义审读和篇幅闭环仍未达到可用标准。

## 4. 真实创作暴露的缺陷

### P1：运行时没有长篇自主创作能力

`generate` 路径仍产出固定两章和模板段落。若没有外部样稿与提案接口，系统无法完成 2 万字作品，也没有按章节依赖自动推进、失败重试、暂停和恢复的创作 run。

改进：建立 Novel Orchestrator，以 StoryMap 章节为任务图；每章执行 context build → draft → critique → revise → adopt gate，并持久化 run、成本、输入锚点、失败原因和恢复点。

### P1：审读是固定规则样例，不是语义审读

15 章都得到同类“增加身体感受与迟疑”的 major finding。扫描器固定选择首个 prose block、固定诊断和固定补句，不能识别人物一致性、时间线、设定冲突、视角漂移、重复意象或跨章因果。

改进：拆成单章审读、跨章连续性审读和全书主题审读；finding 必须携带实际证据、蓝图锚点、置信度、影响章节与可验证补丁，且支持“无问题”结果。

### P1：选择修订可能破坏句法

本次用 16 字选择片段执行 polish 后，系统把模板插入到“高楼之间的”之后，产生病句。系统只做字符串替换，不理解选择边界，也没有修订后语法/事实守卫。

改进：选择修订请求增加完整句、前后文窗口与不可变事实；生成结构化 patch 后先跑边界、语法、锚点和 diff 风险检查，默认展示候选，不自动采纳。此次错误修订已用新的正文修订恢复，未进入最终导出。

### P1：目标字数没有闭环

StoryMap 目标合计 20,600 字，实际快照 17,965 字，约为目标的 87%；多个章节低于各自目标，但 UI 仍显示完成并允许全书导出。系统也没有区分中文字符、中文词和英文 word 的统计口径。

改进：统一 `character_count` / `word_count` 口径；为章节设置允许偏差和最低完成线；低于阈值时提示扩写候选，但允许用户带警告采纳和导出。

### P1：缺少作品级完成态与验收门

15 章、快照和导出均成功后，项目 phase 仍为 `writing`。系统没有“首稿完成 / 审读完成 / 可交付”的明确状态，也无法回答哪些门尚未通过。

改进：引入可计算的交付检查清单，不用手工状态覆盖事实；全部章节已采纳、重大 finding 已处理、篇幅满足策略、成功快照与导出共同投影为 delivery readiness。

### P2：StoryMap 编辑深度不足

当前前端可改章节标题、顺序和基础字段，但缺少卷的增删与重排、节拍目标编辑、锚点选择、节拍覆盖和 Save the Cat 结构可视化检查。

改进：把卷、章、节拍做成分层编辑器；显示十五节拍覆盖率、目标字数曲线、POV 分布、人物/关系锚点覆盖，并保留候选影响预览。

### P2：长篇状态载荷不可扩展

`GET /novel/projects/{id}/state` 一次返回全部章节的全部修订和 blocks。2 万字尚可使用，长篇、多修订项目会明显放大首屏载荷和前端内存。

改进：state 只返回章节摘要与 adopted revision 元数据；正文、历史修订和 diff 按章节懒加载，支持 ETag、分页和局部缓存。

### P2：蓝图契约仍过于宽松

蓝图 anchor 的 `payload` 是自由字典。它便于快速扩展，但无法保证人物欲望、需求、关系运动、规则和弧线节点完整，也难以做自动连续性检查。

改进：在 Novel 域内建立分类型 anchor schema 和版本迁移；不要与 Script 的人物、StoryMap 或 Writer 契约复用。

## 5. 优化路线

### Slice A：先让真实修订可信

1. 修正选择编辑的上下文与 patch 守卫。
2. 加入篇幅口径、章节偏差与交付 readiness。
3. 将审读从固定样例替换为可返回零到多条 finding 的真实 reviewer contract。
4. 用《电光美人》固定为 golden regression，验证关键人名、结局不可备份、15 章顺序和导出哈希/结构。

### Slice B：让 Agent 团队能自主完成首稿

1. 实现 Novel Orchestrator 和逐章持久化 run。
2. 为 Writer 提供当前章目标、相邻章摘要、人物状态、世界规则和未解决线索，而不是整书全文。
3. 每章产出 draft candidate，自动审读后仍由用户策略决定是否采纳。
4. 记录成本、时延、上下文来源和失败恢复点。

### Slice C：提升长篇可控性与沉浸体验

1. 完成卷/章/节拍 StoryMap 编辑与结构诊断。
2. 增加人物状态表、关系变化、时间线、伏笔生命周期和主题意象追踪。
3. 正文与历史修订按章懒加载；编辑器扩大有效写作区域，侧栏按需收起。
4. 建立全书级审读与交付报告，支持按风险回到具体段落。
