# ScriptFlow V7 管理后台 UI 审查

## 范围

- 视口：1140 × 1194，DPR 2
- 页面：Agent 能力治理、租户与额度、模型供给弹窗、MCP/沙箱导航
- 目标：平台管理员能快速定位异常、理解对象关系并安全完成治理操作

## 结论

当前后台具备真实数据与操作入口，但页面结构仍是单组件工程控制台。最严重的问题不是视觉风格，而是双重导航、内容宽度失衡、对象关系缺乏主从层级，以及窄视口下表格和弹窗不可用。

## 证据与问题

1. `01-agent-capabilities.png`：侧栏和顶部二级导航重复表达同一组页面；主标题尺度过大，首屏只看到局部卡片；模板、工具组、挂载矩阵没有形成可理解的依赖关系。
2. `02-tenants.png`：窄视口下页面只利用左侧约四分之一宽度，大面积留白；租户表被截断，操作列不可见；创建、搜索、指标、表格缺少桌面与窄屏两套布局策略。
3. `03-mcp-sandbox.png`：弹窗在窄视口中压缩到近乎不可用，标签、输入值和按钮发生断行/裁切；底层页面状态仍可见但语义焦点不清晰。

## 结构性风险

- `App.vue` 同时承担认证、八类数据加载、全部页面、全部弹窗和全部写操作，状态容易串扰，无法独立测试页面行为。
- 所有后台数据在登录后一次性并行加载，页面导航不是路由，无法深链、刷新恢复或按权限拆分。
- 桌面侧栏与移动导航在 801–1200px 区间缺少中间态。
- 表格没有窄屏替代视图、横向滚动提示、固定关键列或列优先级。
- 弹窗缺少最大高度、内部滚动、焦点圈定、Escape 关闭与关闭后焦点恢复的明确实现。
- 图标使用文字符号，语义、字形一致性和屏幕阅读器体验不稳定。

## 建议优先级

### P0

- 将页面拆成真实路由和独立视图，只保留一套全局导航。
- 建立 `AdminLayout / PageHeader / DataTable / EmptyState / Modal` 基础组件。
- 修复 800–1200px 响应式布局、表格溢出与弹窗可用性。
- 让弹窗拥有焦点圈定、Escape、滚动锁和关闭后焦点恢复。

### P1

- 重新组织能力页为“角色 → 已挂载工具组 → Skills → MCP 权限”的主从关系。
- 首页改为异常优先的运营总览，而非导航后直接进入租户列表。
- 每个页面独立加载、错误和空状态；危险操作增加影响范围与审计预览。

### P2

- 统一中文术语、状态标签、按钮层级、图标库、字号和间距 token。
- 加入键盘、200% 缩放、窄屏、空数据、长文本和错误状态的视觉回归测试。

## 证据限制

截图可以确认布局、层级与可见交互风险，但不能单独证明完整 WCAG 合规。键盘顺序、焦点圈定、屏幕阅读器名称和颜色对比仍需自动化与人工验证。
