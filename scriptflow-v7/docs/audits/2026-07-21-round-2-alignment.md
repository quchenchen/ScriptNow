# ScriptFlow V7 第二轮研发与对齐记录

日期：2026-07-21

## 本轮结论

Creator、Admin 与 Backend 已恢复到可完整自动化测试和本地预览的状态。本轮优先修复了会污染真实创作事实、误导用户决策或让已配置能力无法进入运行时的断点；未把尚未验证的外部能力包装成“已可用”。

## 已完成

- 章节生成不再返回固定中文占位正文。主笔读取创作语言、已采纳方向、蓝图、当前章节和最近确认稿，真实模型输出只形成候选。
- 章节点击只负责导航；确认稿、最新版候选和替换确认形成独立动作。旧确认稿在新候选被明确确认前保持有效。
- Agent 真实调用后写入本次上下文状态；创作搭档不再用模型名或内部事件码冒充用户信息。
- 无需确认的已批准 MCP 工具可从运行快照构造 MCPClient 并注入 AgentScope Toolkit；stdio 连接在失败路径也会关闭。
- 后台形成 `工具发现 → 白名单 → 工具组 → 角色挂载 → 运行快照` 操作链。需要确认的 MCP 暂不挂载，避免越过授权。
- UI 语言切换位于 Creator 顶栏、登录/欢迎页和 Admin 顶栏；选择跨应用持久化，并开始覆盖小说创意、蓝图、StoryMap 和写作主区域。界面语言不修改作品创作语言。
- MCP 能力审计已更新为当前真实状态。

## 验证证据

- Backend：141 项测试全部通过。
- Frontend：13 个测试文件、27 项测试全部通过。
- Creator 与 Admin TypeScript 检查及生产构建通过。
- 本地健康检查：Creator `5174`、Admin `5173`、Backend `8000/health` 均返回 200。
- 本地开发账号登录接口返回 200。

## 仍保持关闭或待下一轮验证

- 需要用户确认的 MCP 调用尚缺 `RequireUserConfirmEvent → 决策 → 原调用续跑`，因此保持安全禁用。
- 尚无真实 MCP Server，市场雷达、网页资料检索与断连降级仍需 tracer bullet，不能标记为产品可用。
- MCP 工具 Schema digest、风险等级、数据出境标签与 Research Snapshot 尚未建立。
- 深层业务页面仍有未迁入词典的中文文案；当前切换已覆盖应用框架和小说主流程，不代表全站翻译完成。
- 真实长章节单次模型生成仍需要分段生成、质量门和续写恢复策略；当前实现解决契约与占位污染，不宣称已完成长篇生产吞吐验证。

## 下一轮优先级

1. 建立本地只读 MCP 测试 Server，完成调用事件、失败降级和 Dock 可观测性。
2. 完成确认型 MCP 的可恢复运行协议，再允许写入、下载或携带作品内容的外部工具。
3. 将 Script、Review、Packaging 和 Admin 深层文案迁入同一 i18n 词典，并补双语 UI 快照测试。
4. 用英文改编项目和中文原创项目各跑一次真实模型长章分段生成，记录上下文、记忆、成本与质量门结果。
