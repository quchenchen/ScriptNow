# ScriptFlow V6 — 产品设计方案

> 用于 UI 设计参考。不含技术实现细节，专注产品逻辑与交互规范。

---

## 一、产品定位

**一句话**：AI Agent 团队驱动的剧本创作平台——创作者是指挥，Agent 是团队。

**核心隐喻**：**生长（Growing）** 而非拼凑。

- 不是"输入 Prompt → 输出文本"的工具
- 是"埋下种子 → Agent 精密发散 → 创作者选择方向 → 蓝图铺开 → 逐场生长"的创作伙伴

**竞品差异**：
| | ScriptFlow | StoryPlay | 传统AI写作 |
|---|---|---|---|
| 主界面 | 三栏工作台（目录/作品/上下文） | 任务列表 | 聊天窗口 |
| Agent角色 | 多Agent团队（导演/架构师/写作者） | 单Agent | 无角色概念 |
| 创作模式 | Candidate→Adopt→Revision循环 | 生成→评估 | 一次性生成 |
| 叙事结构 | 7种全球公认结构可选 | 无 | 无 |
| 媒介 | 7种（竖屏/横屏/电影/动画/小说/短篇/互动） | 少数 | 无 |

## 二、用户画像

### 主要用户：职业编剧/内容创作者

**场景**：接了一个 80 集竖屏短剧的改编任务，有一本 30 万字原著。

**核心需求**：
1. 我不想从头写——AI 帮我发散方向，我选一个最好的
2. 改了第三集的对白，第一集埋的伏笔不能断
3. 每集必须控制在 3 分钟，不能写到 5 分钟
4. 我告诉 Agent "这段对话太冷"，它应该理解我的意思重写
5. 80 集的结构要清晰——哪些集在铺垫、哪些集在对抗、哪些集在收束

**痛点**：
- 现有 AI 写作工具是"一次性生成"，改不了、调不了
- 改编原著时，角色关系和伏笔散落在 30 万字里，改一处容易断链
- 竖屏短剧有时间限制，但没有工具帮我控制每场时长

```
                    ┌──────────────┐
                    │ 1. 创建项目   │ Wizard·4步
                    │ 选类型/媒介   │ 小说/剧本×原创/改编
                    │ 选叙事结构    │ 7种结构可选
                    │ 设规模参数   │ 集数/场数/分钟
                    └──────┬───────┘
                           │
                    ┌──────▼───────┐
                    │ 2. 创意发散   │ Agent 创意导演
                    │ 3个StoryCore  │ 从5个角度折射用户意图
                    │ 每个附解释    │
                    └──────┬───────┘
                           │
              ┌────────────▼────────────┐
              │ 3. 审稿·采用 (决策阶段) │ 用户选择最佳方向
              │ ▸ 查看候选详情          │ 也可以不采用·请求修订
              │ ▸ 采用最佳方向          │
              └────────────┬────────────┘
                           │
                    ┌──────▼───────┐
                    │ 4. 蓝图规划   │ Agent 架构规划师
                    │ 叙事弧线拆分  │ 按选定结构拆分段落
                    │ 人物弧线     │ 每段：冲突/情感/状态
                    │ 关键事件·伏笔 │
                    └──────┬───────┘
                           │
                    ┌──────▼───────┐
                    │ 5. StoryMap  │ 目录生成
                    │ 集×场 结构   │ 每单元继承段落目标
                    │ 左侧目录面板  │
                    └──────┬───────┘
                           │
           ┌───────────────▼───────────────┐
           │ 6. 创作循环 (逐单元推进)       │
           │                               │
           │  选择单元 → 生成正文候选        │
           │       ↓                       │
           │  查看候选 → 反馈修订？          │
           │    ├─ 满意 → 采用正文          │
           │    └─ 不满意 → Agent对话修订    │
           │           ↓                   │
           │       Agent改版 → 再审查      │
           │                               │
           │  采用后：                      │
           │  → 角色状态更新               │
           │  → 伏笔账本同步               │
           │  → 连续性检测                 │
           │  → 下一单元                   │
           └───────────────────────────────┘
```

### 页面2：创建向导 `/create` （4步）

**Step 1**：选择创作类型（4选1）
- 创作一部小说 / 创作一个剧本 / 改编→小说 / 改编→剧本

**Step 2**：给团队种子
- 项目名称
- 原创：主题/灵感/梗概文本
- 改编：【粘贴文本】【上传文件】【稍后添加】三选一

**Step 3**：设定创作基调
- 题材（悬疑/都市/古装/科幻/言情/喜剧/奇幻/现实）
- 目标受众（大众/女频/男频/青少年/文艺）
- 创作媒介（7选1：竖屏短剧/横屏网剧/电影/动画/小说/短篇/互动）
- 叙事结构（7选1：三幕/五幕/起承转合/英雄之旅/救猫咪/八序列/菲尔德）
- 集数/每集场数/单集分钟（剧本媒体）
- 风格方向

**Step 4**：确认并创建

### 页面3：工作台 `/projects/:id/:space/:groupId?/:unitId?`

## 五、核心交互模式

### 模式1：Candidate → Adopt → Revision 循环

这是整个产品最核心的交互。每一处 AI 产出都遵循这个模式。

```
Agent 生成候选
    ↓
用户审查
    ├─ 采用 → 写入 Project Truth → 下一阶段
    └─ 不采用 → Agent对话反馈 → Agent修订 → 新候选
```

**适用场景**：
- StoryCore 候选（3个方向→采用1个）
- 正文候选（生成→审查→采用或修订）
- 角色变更候选（采用后写入 StoryBible）

**UI规范**：
- 候选区域显示为 Agent 消息卡片（左侧蓝色边框）
- 用户反馈显示为用户消息卡片（左侧绿色边框）
- 修订版显示为新 Agent 消息卡片
- 每个 Agent 卡片底部有"采用此版"按钮

### 模式2：阶段门控

不同阶段只显示相关 Tab：

| 阶段 | 可见Tab | 说明 |
|------|---------|------|
| 决策 | 审稿·故事 | 有待处理的 StoryCore 候选 |
| 规划 | 蓝图·审稿·故事 | StoryCore 已采用·等待蓝图 |
| 创作 | 全部 | 蓝图完成·开始写作 |

顶栏阶段指示器：`▶ 决策` / `▶ 规划` / `▶ 创作`

### 模式3：Agent 对话流

正文生成和修订通过 Agent 对话进行，不是独立表单：

```
🤖 写作者 · EP01-SC01·雨痕·湖岸线
│  暴雨砸在黑曜石地面上...
│  [采用此稿]
│
👤 你
│  开头太慢，直接从门铃响切入
│
🤖 写作者 (修订)
│  门铃响了两次。她没动。第三次响起时...
│  [采用此版]
│
┌─────────────────────────────┐
│ 告诉写作者...          [发送] │
└─────────────────────────────┘
```

## 六、关键数据对象

### 项目配置
- 创作类型（原创小说/原创剧本/改编小说/改编剧本）
- 媒介类型（7种·每种有独立默认参数）
- 叙事结构（7种·每种有独立弧线名称）
- 规模参数（集数/场数/分钟/字数）
- 风格方向

### StoryCore（故事种子）
- 标题 · Logline · 戏剧问题
- 主角 · 核心冲突 · 叙事承诺
- 改编策略（改编项目）

### Story Architecture（故事蓝图）
- 创作主张（thesis）
- 叙事策略（approach）
- 叙事弧线列表（每个弧线：名称/集范围/核心冲突/情感落点/人物状态/关键事件/伏笔安排）

### StoryMap（作品目录）
- 分组（Volume/Episode）+ 单元（Chapter/Scene）
- 每个单元：标题/意图/状态/关联正文ID

### Manuscript（正文）
- 正文单元 + 候选版本
- 状态变化声明 + 线索动作 + 连续性报告

### StoryBible（故事圣经）
- 角色/组织 + 当前状态 + 冻结标志
- 关系 + 叙事线程 + 伏笔记录

## 七、设计系统原则

### 视觉
- **基调**：暗色专业工具（Linear 风格）+ 温暖细节（Claude 风格）
- **色彩语义**：
  - 青色 `#22d3ee` — 用户操作 / 前终端
  - 翠绿 `#34d399` — Agent 执行 / 采用 / 通过
  - 玫红 `#fb7185` — 决策点 / 拒绝 / 不通过
  - 紫色 `#a78bfa` — 规划 / 同步 / 蓝图
  - 琥珀 `#fbbf24` — 目录 / 导航 / 循环
- **字体**：系统无衬线（Inter/SF Pro/PingFang SC）
- **间距**：8px 基准网格

### 交互
- **渐进披露**：不一次性展示所有信息，随阶段展开
- **即时反馈**：Agent 工作中显示动画指标
- **可逆操作**：采用/拒绝都可撤销
- **上下文可见**：始终显示当前创作状态和连续性信息

### 内容
- **以作品为主语**：界面标题用"第3场·门厅对峙"而非"Agent 生成的内容"
- **中文优先**：所有 Agent 输出和 UI 文案使用中文
- **具体而非抽象**：状态用"郭小鹏已2集未出场"而非"风险等级:2"

## 八、创作参数参考值

### 竖屏短剧（默认）
- 80 集 × 3 场 × 3 分钟
- ~200 字/分钟 → ~600 字/集 → 每场 ~200 字
- 以近景和特写为主，极少远景
- 对白尖锐、有潜台词

### 横屏网剧
- 24 集 × 6 场 × 30 分钟
- ~180 字/分钟 → 标准影视构图
- 允许中远景、群戏

### 电影剧本
- 1 部 × 45 场 × 110 分钟
- ~150 字/分钟 → 标准剧本格式

### 长篇小说
- 12 章 × 无场次限制
- 叙事文本，内心独白

_详见 `medium_profiles.py` — 7 种媒介完整参数。_

## 九、数据链（可回溯）

```
Project
  ├─ ProjectPlan (medium_key, story_structure, timing)
  ├─ StoryCore (adopted)
  ├─ StoryArchitecture
  │     └─ NarrativeArc[] (thesis, arcs with timing)
  ├─ StoryMapGroup[]
  │     └─ StoryMapUnit[] (title, status, manuscript_unit_id)
  ├─ ManuscriptUnit[]
  │     ├─ ManuscriptCandidate[] (content, state_delta, thread_actions)
  │     └─ ManuscriptDocumentVersion[] (content versions)
  ├─ NarrativeEntity[] (character states)
  ├─ NarrativeThread[] (foreshadows)
  ├─ CreativeDirective[] (user rules)
  └─ ContinuityAlert[]
```

每个对象记录创建者、时间戳、状态变更历史。
