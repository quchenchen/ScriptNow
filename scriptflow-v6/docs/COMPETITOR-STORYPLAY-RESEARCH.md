# StoryPlay 第一轮竞品拆解与 ScriptFlow 转译策略

_调研日期：2026-07-16。创作页在当前环境返回 403；飞书资料因本地认证缺失未能读取。本轮依据官网公开内容、公开索引与公开界面截图，只形成可验证的第一轮判断，不推测其内部技术实现。_

## 1. 已确认的产品能力

1. 入口以具体创作任务组织：网文改编、剧本改写、剧本原创／新建剧本，而不是先让用户理解 Agent。
2. 灵感策划可从简单想法生成多个故事设定方案，并允许设置目标受众、题材等边界。
3. 网文导入后可以拆出章纲，再生成短剧剧本；公开用户反馈认为正文仍需要人工调整台词。
4. 剧本评估从“作者意图”和“观众感受”两个角度逐场拆解，并使用图形化结果呈现。
5. 商业入口使用会员和点数／额度，而不是要求用户自行配置模型。
6. 公开介绍强调策划、创作、分镜的一站式可视化流程和多 Agent 协作。

## 2. 对方当前更强的地方

- 创作任务入口成熟，用户一眼知道能做什么。
- 改编链路更接近生产：导入原作、拆章纲、形成剧本。
- 评估能力已经产品化，而不是一句“Agent 会审稿”。
- 套餐与消耗更接近可运营产品。
- 页面信息密度与工具感强，能让专业用户迅速进入工作状态。

## 3. ScriptFlow 不能照搬的部分

- 不把创作压成固定流水线；用户可以从任意成熟度的作品状态开始。
- 不把 Agent 对话作为主界面，也不让 Agent 静默覆盖作品。
- 不把多个生成按钮等同于多 Agent；每个任务必须有 Context Pack、交付物、依据和决策动作。
- 不只做生成后的评分；连续性系统必须在写作前约束、写作后校验、采用后更新状态。
- 不向普通用户暴露模型选择和供应商配置。

## 4. 应吸收并升级的产品结构

### A. 首页：按创作任务进入

- 原创小说
- 原创剧本
- 小说／故事改编剧本
- 剧本／故事改编小说
- 导入已有作品继续创作
- 评估与诊断已有作品

### B. 项目驾驶舱：始终回答三个问题

1. 作品现在长到哪里？
2. Agent Team 当前在做什么？
3. 是否需要用户判断？

### C. 创作对象层

```text
Source Canon
→ Story Core
→ Character / World / Relationship Truth
→ Story Map
→ Chapter / Episode / Scene
→ Revision Candidate
```

### D. 叙事控制层

- 角色状态与知识边界
- 场景、时间线与物品状态
- 情节因果链
- Promise–Payoff 伏笔账本
- 情绪曲线与关系变化
- Continuity Alert 与修改影响分析

### E. 评估层

评估不只给总分，分成：作者意图达成度、观众体验、角色可信度、节奏、情绪推进、伏笔有效性、媒介适配度。每个结论必须定位到章节／场次并提供证据，可一键生成 Revision Brief，但不能自动改写已采用正文。

## 5. 平台模型与收费策略

用户购买的是创作能力与质量等级：

- 基础创作：策划、轻量续写、格式整理。
- 专业创作：长上下文、角色一致性、章节生成、深度改编。
- 深度审阅：多视角评估、连续性扫描、Revision Candidate。
- 制作扩展：分镜、资产、视频前置规划。

平台按任务类型和质量门槛路由 LLM。前端显示预计额度与能力等级，不显示具体模型。失败重试、供应商切换和降级策略由平台承担。

## 6. 最近开发优先级调整

1. 把“项目状态／Agent 当前任务／等待用户决策”做成全局可见的 Project Pulse。
2. 完成导入原作 → Source Canon → Adaptation Map 的真实链路。
3. 完成 Story Core → 第一章候选 → 连续性检查 → 采用 → 状态更新闭环。
4. 增加作品评估入口和场景级证据视图。
5. 建立 Capability Tier、额度预估和平台 Model Router，管理端与创作端分离。
