# 全局作品深度规划：填补 StoryCore 与 StoryMap 之间的鸿沟

## 诊断

```
当前路径:
  StoryCore (300字梗概) ──跳过──→ StoryMap (240个空"待规划")
                    ↑
            这里缺了编剧最核心的工作
```

StoryCore 回答的是"这个故事讲什么"，StoryMap 挂的是"这个故事有多少个容器"。
但编剧在两者之间必须做一件事：**把这个故事拆成有生命的段落**。

这是**故事架构**——不在代码里，不在数据库里，但它决定了后面全部章节写出来是不是一个整体。

## 方案：引入 Story Architecture 层

不是加一个数据库表那么简单。是加一个**Agent 驱动的规划阶段**，
让创作者的意图被"精密发散"成结构化的故事蓝图，然后 StoryMap 从蓝图中生长出来。

### 三层规划模型

```
StoryCore (种子)        →  我选"黑冰·双强博弈 · 三分钟裁决"
                              │
Story Architecture (蓝图) →  Agent 从5个维度发散规划:
                              │  1. 叙事弧线: 80集如何切分为5-8个叙事段落
                              │  2. 人物轨迹: 汪静飞/郭小鹏在每个段落的心理位置
                              │  3. 关键事件: 每个段落不可跳过的转折点
                              │  4. 悬念布局: 伏笔在哪个段落埋设/强化/回收
                              │  5. 情感曲线: 观众应该在哪个段落感受到什么
                              │
StoryMap (目录)         →  基于蓝图自动生成 Episode/Scene 结构
                              │  每个 Unit 不再是"待规划"，而是继承了:
                              │  - 所属叙事段落的目标
                              │  - 人物的当前状态
                              │  - 应该推进的悬念
                              │  - 应该达到的情感效果
```

### 为什么这是产品缺陷而不是技术缺陷

即使 StoryMap 联动 Bug 修好了（B1），即使文档内容正确保存了（B2），
**创作仍然会断**。因为问题不在"数据没存对"，在"中间缺了一层思考"。

一个编剧不会从"女主角潜入别墅复仇"直接跳到"第1集第1场：门厅"。
她会先画出：
- 这个故事的呼吸节奏是什么
- 男女主角在哪几集关系转折
- 哪些集是"暴风雨前的宁静"，哪些是"高潮前的攀升"
- 每一段要给观众留下什么印象

这些不是"元数据"，是**创作决策**。目前系统没有给 Agent 发散的机制，
也没有给创作者审视和调整这些决策的界面。

### 具体落地方案

#### 第一步：Story Architecture Agent

采用 StoryCore 后，不是跳到 StoryMap，而是进入**故事架构规划**阶段。

Agent 产出：

```
《黑冰·双强博弈》全局蓝图

━━ 叙事段落 ━━
段落1 · 潜入（EP01-12）：汪静飞进入郭小鹏的世界
  核心冲突：信任如何建立——汪静飞的伪装 vs 郭小鹏的试探
  情感落点：两人第一次真正"看见"对方（EP11-12）
  不可跳过：EP01接任务→EP04首次见面→EP08第一次私下交谈

段落2 · 接近（EP13-28）：汪静飞深入核心圈
  核心冲突：证据在积累，但情感也在积累——取证 vs 动摇
  情感落点：汪静飞第一次为郭小鹏说谎（EP27）
  不可跳过：EP15郭小鹏暴露脆弱→EP22两人差点被发现→EP27情感临界点

段落3 · 裂痕（EP29-45）：信任开始崩塌
...

段落4 · 对决（EP46-65）：正式摊牌
...

段落5 · 代价（EP66-78）：真相的代价
...

段落6 · 审判（EP79-80）：最终裁决
  核心冲突：法律正义 vs 个人正义
  情感落点：两人最后的对话——不是审讯，是告别
  不可跳过：EP79郭小鹏的终场独白→EP80汪静飞的选择
```

#### 第二步：每个段落继承到 StoryMap

不再是 240 个空壳。每个 Episode 知道自己在哪个段落、要完成什么：

```
EP01 · 潜入段落
  目标: 建立世界观 + 汪静飞的初始动机
  SC01: 戴主席电话郭小鹏——权力的第一笔
  SC02: 汪静飞接任务——"你确定要接这个案子？"
  SC03: 两人尚未见面——分别准备、彼此预感
  应埋设: 郭小鹏对手下的绝对控制力（为EP08背叛埋线）
```

#### 第三步：场次生成时自动注入段落目标

Agent 生成 SC01 时，不只看到 StoryCore 梗概，还看到：
- "这段落在叙事弧线的位置：潜入段落·第1集"
- "本集目标：建立世界观+汪静飞的初始动机"
- "本集情感落点：权力感（郭小鹏）vs 紧迫感（汪静飞）"
- "应埋设：郭小鹏的控制力（为后续背叛铺垫）"

这样产出的每一场戏，都**知道自己在整部作品中的位置**。

#### 第四步：创作时可以随时回到蓝图调整

如果写到 EP35 发现"对决应该提前到 EP40"，不只是改一个数字——
Agent 会重新推演：
- 哪些事件需要前移
- 情感曲线是否需要调整
- 伏笔回收时间线是否受影响
- 哪个段落的叙事压力增加了

这就是"精密发散"和"成长"——不只是一个数据结构，
是一个能理解故事结构、主动推演影响的系统。

---

## 与 V6 现有架构的关系

V6 的 `StoryMapGroup` / `StoryMapUnit` 是正确的基础数据结构。
缺的不是新表，是**填充这些表的 Agent 规划阶段**。

新增：
- `StoryArchitecture` 模型或 JSON 文档（一个项目一份）
- `StoryArcAgent` — 专门负责从 StoryCore + 创作指令中推演叙事结构
- 一个**可视化蓝图界面** — 不是表格，是时间线/结点图
- 蓝图变化 → 自动计算的**影响分析** — 类似 V6 已有的 `ProjectPlanImpact` 模式
