# 18 · LLM 正文编辑器闭环

- **Status**: in-progress
- **Parent**: Creator Execution Phase C
- **Blocked by**: 17B, 17C
- **Blocks**: 原创剧本审稿、小说基础闭环、Ralph Revision

## Product outcome

创作者可以直接编辑 Chapter/Scene 正文，选择一段内容后执行缩写、扩写、润色、对白调整、节奏调整或自定义要求。AI 修改始终先形成 Candidate Revision；创作者可比较、继续调整、采用或拒绝，只有采用后才更新正文与连续性状态。

## Editor boundary

- 参考 `lobehub/lobe-editor` 的选区工具栏、局部流式修改和“AI 是可见协作者”模式。
- 不直接在 Vue 3 主应用嵌入其 React 19 UI 包；避免 React、React DOM、Ant Design、Lobe UI 双框架运行时。
- 第一阶段建立与编辑器实现无关的 `EditorDocument / SelectionAnchor / AiEditCommand / CandidateRevision` 协议。
- Vue 编辑层优先评估原生 Lexical kernel 适配或 Vue 生态编辑器；无论替换何种内核，Revision API 与保存协议保持不变。
- 实时协作 Yjs 属于后续能力，不作为单人 LLM 编辑闭环的前置条件。

## Acceptance

- [x] 正文可编辑，具备 dirty / saving / saved / failed 状态和离开保护
- [x] 自动保存使用基线版本号，冲突时禁止静默覆盖
- [x] 选区锚点包含文本、范围、前后文和基线版本
- [x] 支持缩写、扩写、润色、对白、节奏、自定义六类操作
- [x] LLM 仅返回局部 Candidate Revision，不直接修改采用正文
- [x] 流式候选不会污染正式正文；中断可安全丢弃
- [x] diff 支持采用、拒绝、继续调整和 stale base 重试
- [x] 采用后记录 lineage，并生成角色/关系/伏笔影响候选
- [x] Chapter 与 Scene 都通过同一编辑协议，显示各自专业术语
- [x] Chapter 保存 POV / 叙述人称 / 时间位置；Scene 保存场景头 / 地点 / 时间 / 出场人物，并随正文版本进入 Agent 上下文
- [ ] 编辑、选区 AI、冲突恢复和键盘操作具备组件/E2E 测试

## Gate C tracer

1. 打开一段已采用正文并直接修改，自动保存成功。
2. 选择一个段落执行“压缩到原长度的 60%，保持事实和语气”。
3. 页面以局部 diff 展示流式候选，原正文保持不变。
4. 在候选生成期间修改基线，采用操作返回 stale 并要求重新比较。
5. 重新生成并采用，正文版本、Revision lineage、连续性影响记录可追溯。

## 2026-07-16 implementation evidence

- 新增正文版本历史表和乐观锁保存 API；直接编辑只更新已采用正文，每次保存生成递增版本。
- 新增 Manuscript Edit Revision，保存选区、上下文、模式、保留项、替换候选、理由和基线版本。
- 23 个后端测试通过，其中覆盖“候选不改正文”“采用生成版本 2”“人工先保存后 AI 候选 stale”“采用后才生成连续性影响候选”“流式准备中断不留候选也不改正文”“专业正文元数据随版本保存与恢复”。
- 正文组件可编辑并显示保存状态；章节切换、空间切换、返回 Dashboard 前强制落盘。
- 正文版本历史可展开查看；回退旧版本会创建一个可追溯的新版本，不覆盖历史。
- AI 局部候选采用后生成独立的故事变化候选；创作者确认后才写入人物状态、关系、伏笔或世界事实，忽略则不影响后续创作。
- 根据创作者反馈，选区工具改为不占正文流的浮层；已采用正文不再重复展示旧候选影响，未采用候选影响折叠显示。
- 根据正文优先原则，左侧目录压缩到 184px，正文取消窄纸最大宽度并减少双层留白；右侧永久协作区保持用户指定的约 1/3。
- 新增 NDJSON 流式候选协议：浏览器逐段显示候选，可随时停止并丢弃；服务端只在完整流交付后落 Candidate Revision。当前 AgentScope 上游调用仍先完成结构化生成再分段交付，后续可继续下沉到模型 token passthrough，不影响编辑协议。
- Chapter 编辑器增加视角人物、叙述人称和时间位置；Scene 编辑器增加内外景、地点、时间和出场人物。这些字段与正文共用乐观锁版本，并进入后续写作和局部编辑 Agent 的输入。
- 待完成：完整 E2E 与键盘/中断交互覆盖。
- 隔离数据库浏览器 Gate 已通过两条真实路径：2 章小说与 1 集×2 场剧本均完成创建、Story Core 采用、正文采用、直接编辑、专业元数据保存、刷新恢复；小说验证 AI 候选拒绝不改 v2，剧本验证 v2 回退为新 v3。
- 浏览器验收发现并修复跨项目编辑会话泄漏：从小说直接创建剧本时，旧 AI Revision 曾短暂残留；创建 Project 现在显式清空 Revision、选区、正文和传播状态。
- 自动化浏览器测试工具链仍待 Gate F 建立，因此本项保持未勾选；当前运行 Gate 证据不冒充可重复 CI E2E。
