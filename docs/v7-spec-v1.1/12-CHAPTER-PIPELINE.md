# 章节级生产管线

状态：已实施基线
适用：Novel 普通创作与故事归化；两者使用各自正文和审读契约，只共享运行、事件与版本基础设施。

## 1. 目标

章节不是一次 Agent 调用的显示结果，而是最小的可恢复生产单元。每章必须能够独立生成、失败、重试、审读、人工修订、采纳和追溯；单章失败不得使整书管线失效。

章节数量、顺序、目标篇幅、语言、市场、题材和质量阈值来自项目契约、已确认蓝图或作者交互，不在代码和测试中写死。

## 2. 章节契约

蓝图中的每个生产工作包只对应一个可交付章节，并具有：

- 稳定章节键、章节序号、标题；
- 源素材范围与叙事功能；
- 目标设计、依赖章节、连续性输入；
- 必须保护的故事基因与验收条件；
- 可选目标篇幅；仅在项目契约已经设置时使用。

旧数据中的多章节工作包继续只读兼容；重建蓝图后按一章一包生产。

## 3. 双状态模型

决策状态保护作者事实：

`candidate → adopted → superseded`

生产状态描述运行事实：

`drafting → validating → review_pending → ready_for_decision → adopted`

异常与回路：

- 任意生成或校验失败进入 `failed`，可创建新版本重试；
- 审读发现阻断问题进入 `revision_required`；
- 人工修订创建独立版本，回到 `review_pending`；
- 只有 `ready_for_decision` 才允许作者采纳。

生产状态不是 Candidate，不得伪装为用户已经确认的创作事实。

## 4. 上下文与版本

每次章节运行持久化上下文快照，至少记录：

- 已确认蓝图及版本；
- 当前章节契约；
- 前序已采纳章节的单元 ID 与版本；
- 目标故事契约版本。

后续章节只读取前序章节的最新已采纳版本。未采纳候选、失败运行和被取代版本不得污染后续上下文。人工修订通过 `source_unit_id` 保留版本血缘。

## 5. AgentScope 与事件

生成使用 AgentScope 的 `ThinkingBlock`、工具事件和 `TextBlock` 原生流，不以字符串规则伪造思考或正文。正文候选只从正文块建立；思考与工具事件进入运行流和创作搭档视图。

章节运行开始即落盘；完成后写入结构化候选，失败时写入可读失败原因。项目事件只记录状态变化，不为轮询重复写入同一提示。

## 6. 作者交互

- 生成中：只读状态，不允许编辑；
- 生成完成：先进行质量审读；
- 审读后：作者可人工修订并另存新版本；
- 采纳前：任何候选都不属于确认正文；
- 采纳后：该版本成为后续章节上下文和最终合稿来源。

工作台默认只渲染当前章节。左侧切换章节，中部预览或编辑候选，右侧显示章节契约与管线状态，避免整书正文一次铺满页面。

## 7. 质量门禁

最低结构门禁包括正文、再创作依据、故事基因追踪和质量自检。Agent 自检中的失败项必须进入审读发现，不能用“降级成功”绕过。类型、风格和市场质量标准由所选 SkillPlan 与项目契约注入。

## 8. 验收

1. 创建任意章节数量的蓝图，界面不依赖固定数量。
2. 生成开始后刷新页面，仍能看到运行状态。
3. 单章失败后其他章节与已采纳正文可继续使用。
4. 未审读候选不能采纳。
5. 人工修订产生新版本且保留来源版本。
6. 后续章节上下文引用最新已采纳版本。
7. 合稿仅包含每章当前已采纳版本。
