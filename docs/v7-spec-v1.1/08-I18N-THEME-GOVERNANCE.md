# V7 界面国际化与主题治理

## 1. 边界

ScriptNow 同时存在三种不得混淆的语言：

1. **界面语言**：导航、按钮、状态、错误、帮助文本，由用户随时切换。
2. **作品创作语言**：项目创建时选择，约束 Agent 的创意、蓝图、正文、审读和包装输出。
3. **素材语言**：上传文件的原始语言，只用于解析、检索、引用和忠实度校验。

切换界面语言不得翻译或改写作品、项目名称、Agent 产物、素材引文与用户输入。作品语言改变必须走显式项目操作，不能由界面语言联动。

## 2. 当前实现

- 共享状态：`@scriptnow/shared/useLocale`，负责持久化、跨标签同步与 `<html lang>`。
- 共享目录：新页面优先使用稳定 `t()` key；既有高密度工作台由 `sourceMessages` 纳入同一目录，并通过根级 `v-ui-locale` 实时投影，异步插入的弹窗、状态、占位符和可访问名称同样受控。
- 内容边界：作品正文、可编辑区、素材证据、图谱事实与 Agent 原始输出由语义容器自动保护；其他项目名、用户输入与外部内容使用 `data-i18n-skip` 声明不可翻译区域。语言切换只恢复目录记录的界面源文案，不对英文结果做反向猜测。
- 支持界面语言：`zh-CN`、`en-US`。
- 项目创作语言继续使用项目字段 `creative_language`，不复用界面 locale。
- 共享主题：`@scriptnow/shared/useTheme`，支持首次跟随系统及用户显式选择 `light` / `dark`。
- 主题选择写入 `scriptnow-ui-theme`；界面语言写入 `scriptnow-ui-locale`。
- 首次读取时迁移旧本地偏好并删除旧 key；后续只写入 ScriptNow key。

## 3. 文案规则

1. 新增用户可见的静态文案必须进入共享文案目录，不得直接写在模板或业务函数中。
2. 产品术语使用稳定 key，例如 `creator.storyGraph`；翻译不得成为业务枚举或 API 参数。
3. 后端返回稳定错误码和结构化参数；前端按界面语言转换为用户文案。不得直接展示 Pydantic、SQLAlchemy、HTTP 或 Provider 原始异常。
4. 动态值使用参数化消息；数字、日期、货币和复数通过 locale formatter 处理，禁止写死 `toLocaleString('zh-CN')`。
5. 专有名词、人物名、书名、模型名、Provider 名和素材原文默认不翻译。
6. 可访问名称、空态、加载态、确认提示和错误恢复文案与可见文案同步纳入词条。

## 4. 主题规则

1. 组件颜色只能引用语义 token：背景、表面、正文、次级正文、边界、主色、警示色；禁止继续扩散十六进制字面量。
2. 日间与夜间保持相同信息层级和几何布局；主题切换不得导致重排。
3. 图谱节点与关系不能只靠颜色区分，需同时保留文字、线型或图标。
4. 所有表单、弹窗、编辑器、图谱、Dock、焦点态和错误态必须分别在两种主题中验证。
5. 尊重 `prefers-color-scheme` 与 `prefers-reduced-motion`。

## 5. 迁移完成面

### 全局入口与关键链路

- AppShell、登录、欢迎页、管理后台接入共享主题和界面语言。
- 创作现场、故事图谱、Agent Dock、错误态和项目创建向导消除中英混排。
- API 原始错误统一映射为用户可理解文案。

### 业务页面

- 蓝图、StoryMap、逐章/逐场写作、审读、包装、导出、账户与 Agent 团队。
- 管理后台租户、用量、供给、技能、MCP、记忆全部迁入消息目录。

### 质量门

- 测试覆盖共享状态、双端根接入、异步文案翻译、属性翻译、中文恢复和 `data-i18n-skip` 内容边界；新增文案必须同步进入稳定 key 或 source-message 目录。
- 对 `zh-CN`、`en-US` 分别执行关键流程截图回归、键盘测试与窄屏重排测试。
- 两种主题分别运行对比度与 axe 检查。

## 6. 验收标准

- 切换语言后无需刷新，两个 SPA 和所有全局入口同步生效。
- 刷新、重新登录和跨标签页保持界面语言与主题偏好。
- `<html lang>`、`color-scheme`、`data-theme` 与当前状态一致。
- 用户可见区域不出现未解释的开发术语、中英混排或原始后端异常。
- 作品语言和界面语言可独立组合验证。
- 日间/夜间下正文编辑、图谱阅读和管理表格均保持清晰可读。
