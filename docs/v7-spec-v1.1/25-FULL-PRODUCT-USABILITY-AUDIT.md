# ScriptNow 全流程可用性验收

状态：通过
验收日期：2026-07-30
适用版本：v1.1

## 验收目标

本轮验证聚焦最近新增的评审能力，并对现有四领域主流程做回归：

- 项目内评审是否在关键候选形成时以决策检查点主动介入；
- 审读编辑是否自动取得项目正文、候选、版本和事实，而不是再次索要内容；
- 独立评审是否支持上传原稿、持续追问、刷新恢复和 Markdown 可读呈现；
- 小说、剧本、忠实翻译、故事归化、包装和历史入口是否仍可打开；
- 日夜主题、身份会话和旧评审入口迁移是否保持一致。

## 产品结论

### 项目内审读

项目内不再保留一个与创作流程割裂的“完成后评审页”。系统依据领域事件识别当前未决候选，Dock 切换为“审读编辑”，自动装配：

- 当前项目和领域；
- 当前候选及其完整或分段正文；
- 已确认事实与最新修订；
- 当前决策检查点和证据引用。

审读编辑只提出 Finding、证据和修订建议，明确采纳后才改变项目事实。旧的项目评审路由会返回项目创作现场并打开对应检查点。

### 独立评审

独立评审不创建项目，采用持久化连续会话：

- 支持 DOCX、PDF、TXT、Markdown 与 HTML；
- 历史评审收纳为紧凑入口，不占主要对话区域；
- 运行时自动选择准入 Skill，不向创作者铺陈原始 Skill、模型、权限和 Token 信息；
- AgentScope 流式 Block 被合并为可读消息，不逐 Token 创建“分析过程”卡片；
- 表格、标题、列表、引用和代码块由统一 Markdown 渲染器呈现。

## 浏览器验收

### 独立评审

- 连续对话输入存在并可继续追问；
- 报告中的五张 Markdown 表格均渲染为真实表格；
- 页面中不存在原始 `| 要素 |` 表格源码泄漏；
- 历史记录以紧凑入口呈现；
- 页面没有 `Failed to fetch`、`Not Found` 或 500 错误。

### 项目检查点

- 旧 `/projects/:id/review-agent` 地址返回项目创作现场；
- Dock 显示“项目决策检查点”和“审读编辑”；
- 可按需审读并返回创作搭档；
- 页面不显示原始 Skill 清单；
- 当前项目正文由系统自动取得。

### 四领域与周边流程

以下入口完成加载烟测，未出现请求失败或路由错误：

- 小说创作现场；
- 剧本场景写作；
- 忠实翻译工作台；
- 故事归化六阶段工作流；
- 作品包装；
- 项目仪表盘与历史入口。

夜间模式验证了页面背景、正文、Dock 和控件对比度，主题状态可正常切换。

## 当前边界

1. 本轮没有重新发起会消耗外部额度的真实 Provider 创作任务；真实 Provider 黄金回放结果沿用版本基线，不能用本轮本地浏览器烟测替代。
2. Creator 生产包仍有约 689 KB 的单包体积警告。它不阻断功能，但下一轮应按领域路由拆分异步 chunk，避免首次进入加载全部创作模块。
3. 浏览器验收覆盖当前桌面视口与主题状态；响应式规则已有自动化和既有回归，本轮未把所有设备尺寸重新录制为视觉基线。

## 退出门

本轮评审改造达到以下退出条件：

- 项目内审读是主动检查点，不是被动终点；
- 独立评审是连续对话，不是一次性报告；
- Markdown 与流式消息对作者可读；
- 项目材料能够自动进入 Reviewer 上下文；
- 内部运行诊断不污染创作界面；
- 四领域现有主入口未被评审改造破坏。
