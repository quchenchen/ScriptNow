# ScriptNow 原型回归与沉浸式创作优化策略

_版本：v1.0 · 2026-07-20 · 状态：执行中_

## 1. 结论先行

当前实现的领域闭环和可信平台能力已经超过冻结原型，但 Creator 的产品外壳只完成了功能承载，没有达到原型定义的创作体验。最大偏差不是颜色或圆角，而是 **写作时的信息层级和空间状态错误**：全局页面框架、巨型页标题、四 Agent 总览和右侧悬浮 Dock 同时争夺注意力，正文没有成为唯一视觉主角。

因此在 P8 前插入一次 Creator Experience Recovery：先重建可收起的全局 Shell，再恢复进入 Writer 自动切换的沉浸式工作台。不得回退已完成的真实 API、事件、租户、版本和分域契约，也不得复制原型中的演示数据或 localStorage 业务事实。

## 2. 审计依据

- 规格：PRD FR-3.0、FR-3.7、FR-3.8、FR-3.10。
- 冻结原型：已在 2026-07-23 的外部归档中保留，仅在视觉回归需要时定向提取。
- 当前实现：`scriptnow/frontend/apps/creator` 的实际生产构建与本地浏览器预览。
- 原型实测：进入“逐场写作”后自动收起 240px 全局侧栏，保留展开把手；使用紧凑 topbar、当前 Agent Bar、左目录/中正文/右上下文与修订三栏，以及底部横向 Agent Dock。

## 3. 当前偏差与影响

| 层级 | 当前偏差 | 用户影响 | 优先级 |
|---|---|---|---|
| 创作注意力 | Writer 仍位于普通 `page-shell` 中，页标题、通用导航、四 Agent 条和右悬浮 Dock 同屏 | 正文不是视觉中心，长时间写作干扰高 | P0 |
| 沉浸状态 | 没有进入 Writer 自动收起侧栏、离开恢复、手动覆盖和 `⌘/Ctrl+B` | 用户无法稳定进入/退出专注状态 | P0 |
| 空间结构 | Dock 固定在右下，叠压三栏工作台；正文区受 max-width 页面容器二次压缩 | 小屏和修订密集场景可用宽度不足 | P0 |
| 单元聚焦 | 中央画布同时渲染全部已采纳场景/章节，而左栏却表现为单场/单章选择 | 目录选择与正文焦点语义不一致 | P0 |
| 右侧信息 | 当前只有修订面板，缺少“上下文 / 修订痕迹”双 Tab | 创作依据与修改建议无法在同一焦点切换 | P1 |
| 全局 Shell | 缺少 240px 侧栏、项目切换、分阶段导航、账户/用量、拖拽收起、移动抽屉 | 项目内定位和阶段回看成本高 | P1 |
| Agent Bar | 当前固定展示四个 Agent；原型按视图显示当前 Agent、模式、状态和上下文 chips | “当前谁在工作、基于什么工作”不清楚 | P1 |
| Dashboard | 项目卡缺少阶段进度、方向标签、最近事件 | 不能在进入项目之前判断工作状态 | P2 |
| Wizard | 方向、结构与体量的视觉层级和动态提示弱于原型 | 新项目决策缺少足够语境 | P2 |
| 视觉节奏 | 暖纸色和衬线方向基本一致，但工作区沿用营销页大标题和宽松留白 | 工作效率和信息密度不匹配 | P2 |

## 4. 目标体验

创作者从项目进入写作单元时，界面应完成一次可解释、可逆的空间转换：

1. 全局侧栏自动收起，但保留左侧展开把手；自动状态不覆盖用户手动偏好。
2. topbar 收敛为视图标题、保存状态和真实用量；Agent Bar 只显示当前阶段角色和真实上下文。
3. 主区占满剩余视口，只渲染当前场景/章节：左侧目录、中间正文、右侧上下文/修订双 Tab。
4. Agent Dock 保留当前右侧浮动方案；在沉浸模式下限制尺寸并与正文/右栏安全避让。SSE、确认卡、引用和 diff 契约保持不变。
5. 离开 Writer 后恢复进入前的侧栏状态；`⌘/Ctrl+B`、拖拽、双击边缘和移动端抽屉均可用。

### UX-R2 — 原型信息架构回归（P8 同步）

- Dashboard 增加真实阶段进度、方向标签和最近事件。
- Agent Bar 接入当前角色、运行状态、项目/方向/阶段 chips 和设置入口。
- 侧栏账户卡接 P8 的等级、用量与用户中心；未接入数据明确显示未接入。
- 导出与历史版本移动到侧栏项目导航，同时保留 Writer 内就近入口。

### UX-R3 — 视觉与体验硬化（P9）

- 冻结原型与生产构建的关键视图截图基线。
- 空态、错误态、长文本、200 Findings、SSE 展开和移动端视觉回归。
- 字体、色彩、密度、动效和无障碍统一；不追求像素复制演示内容。

## 6. 不可破坏约束

1. Script 与 Novel 继续保留独立 Writer、正文类型、上下文、审读规则、格式和导出组件；只共享无领域含义的 Shell 布局机制。
2. 侧栏状态可以本地保存；正文、候选、事件、快照、用量和记忆必须继续以服务端为事实源。
3. 自动沉浸不得覆盖手动偏好；刷新后不得把用户困在无法展开的状态。
4. Dock 只是事件投影和控制面，不成为第二份正文或运行事实源。
5. 原型中的项目名、人物、tokens、价格和 Agent 文案不得进入生产 seed。

## 7. 量化验收指标

- 1440px 宽度进入 Writer 后，正文可用宽度不低于工作区的 52%；右浮动 Dock 收起/展开均不遮挡正文主操作区。
- 进入/离开 Writer 的布局状态切换在 250ms 内完成，并尊重 reduced-motion。
- 目录点击后中央只存在一个 active 创作单元；刷新保持服务端当前正文，不出现多单元叠放。
- Dock 展开、右栏打开和 200 Findings 同时存在时无水平溢出、无正文操作被遮挡。
- `⌘/Ctrl+B`、Esc、Tab、Enter 可完成侧栏、Dock、选区 popover、修订与确认卡主流程。
- Creator 关键视图在 1440/1024/768/390 四档通过视觉回归；axe serious/critical 为 0。

## 8. 执行顺序

UX-R0 → UX-R1 已于 2026-07-20 完成首轮实现与浏览器验收：Creator Shell、进入 Writer 自动收起、手动展开/快捷键、单场/单章聚焦、分域上下文/审读页签、右悬浮 Dock 限高与收起手柄均已落地；前端 5 个测试文件共 11 项通过，Creator/Admin 生产构建通过。下一步进入 P8，并在实现账户、用量和 Agent 设置时直接填充新 Shell 的真实数据槽位。UX-R2 随 P8 完成，UX-R3 纳入 P9 RC 硬化，避免再做一次外壳重写。
