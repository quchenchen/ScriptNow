# ScriptFlow V6 UI 交互体系

- **Status**: Accepted as interaction source of truth
- **Date**: 2026-07-16
- **Applies to**: Desktop web V6
- **Depends on**: [`V6-PRODUCT-BLUEPRINT.md`](./V6-PRODUCT-BLUEPRINT.md)、ADR-0005

## 交互目标

用户在任何时刻都应知道：自己正在编辑什么、AI 正在做什么、哪些内容已经采用、哪些只是候选、当前动作会影响哪里，以及下一步由谁决定。

交互体系围绕四种确定性建立：

- **位置确定性**：当前项目、空间和正文单位可见并写入 URL。
- **版本确定性**：明确当前采用版本、草稿、候选和未保存修改。
- **责任确定性**：区分 Agent 自动执行、用户决策和系统提醒。
- **影响确定性**：修改前后都能查看受影响对象。

本文的页面规则受 [`V6-HUMAN-AI-INTERACTION-CONSTITUTION.md`](./V6-HUMAN-AI-INTERACTION-CONSTITUTION.md) 约束。AI 主动程度、打断强度、Decision Budget 和异常恢复以该文档为准。

## 全局信息架构

```text
Dashboard
└── Project Workspace
    ├── 专注创作
    ├── 故事规划
    └── 审阅决策
        ├── 上下文工具：来源 / 版本 / Growth Tree / 设置
        └── 项目交付：导出
```

三个模式使用真实链接，支持刷新、复制链接和浏览器前进后退。当前 Chapter/Episode/Scene 进入路径参数或 query；来源、版本、导出等工具使用子路由或带返回来源的覆盖层。面板展开状态可以本地保存，不作为业务状态。

## 工作台框架

工作台不是永久三栏。它根据用户意图切换三种模式，并保持同一作品对象与选择上下文：

| 模式 | 主任务 | 默认布局 | Agent 表现 |
|---|---|---|---|
| 专注创作 | 阅读、书写、局部修改 | 目录 + 大幅编辑纸面 | 退居后台，仅显示可收起任务状态 |
| 故事规划 | 查看因果、结构、来源与影响 | 上下游关系透镜 | 以候选节点和影响提示出现 |
| 审阅决策 | 比较证据与 Revision、拍板 | Decision Inbox + diff | 明确建议、理由与可撤销性 |

模式不是三个独立页面。用户从选区创建候选 Revision 后进入审阅时，必须保留当前 Scene、选区与父 Revision。

### 顶部项目栏

包含返回项目列表、项目名称、Creation Source/Delivery Medium、三个工作模式、全局保存状态、决策收件箱和项目菜单。来源、版本与导出放入上下文或项目入口。模型选择不占据全局高频位置，放入 Agent Task 设置或项目设置。

### 左侧作品目录

创作空间展示 Story Map：Novel 为 Volume/Chapter，Script 为 Episode/Scene。每行只显示名称、必要状态和风险数量。目录负责定位正文，不展示复杂血缘图。

故事世界空间将左栏切换为 Story Core 类型；审查空间切换为问题分组；版本与血缘空间切换为 Branch/Revision 列表。

### 中央主工作区

中央永远承载当前空间的主要对象。创作空间使用结构化编辑器；故事世界使用实体详情；审查使用问题与 diff；版本空间使用比较或 Growth Tree；导出使用范围与检查结果。

### 右侧协作区

右侧协作区不常驻。只有运行中的具体 Task 或当前对象的上下文被用户主动展开时出现；没有关键活动时，编辑器获得完整宽度。它显示结构化 Task、Decision 和 Delivery，不把状态压成聊天流。聊天是补充输入方式，不是团队工作的主界面。

## 导航规则

- Dashboard 项目卡主操作为“继续创作”，恢复上次位置。
- 一级空间切换保留当前采用 Revision，不触发生成或保存。
- 点击风险、审查问题或 Source Reference 跳转到目标对象，并保留返回来源。
- Growth Tree 节点点击打开详情或比较，不把工作台强制切回阶段页面。
- 任何临时弹窗关闭后，焦点回到触发控件。

## 创建项目

创建流程采用四步：

1. **选择目标**：四个任务入口。
2. **提供起点**：原创选择成熟度并输入种子；改编上传 Source Canon、确认使用权。
3. **定义方向**：受众、题材、风格、目标规模；允许跳过非必要项。
4. **确认与创建**：展示项目类型、来源、首个 Agent 任务和可修改摘要。

每一步只要求当前任务所需信息。返回上一步不丢值；关闭含已输入内容的向导时提示保留草稿或放弃。

## 创作编辑器

### Script Editor

Episode 是目录单位，Scene 是主要编辑单位。Scene 内部使用 Scene Heading、Action、Character、Dialogue 等块。用户可直接编辑，块类型通过明确菜单或快捷命令添加。

### Novel Editor

Volume 是可选分组，Chapter 是主要编辑单位。Chapter 保留 POV、状态、目标字数等元数据，正文使用段落编辑。

### 共同编辑行为

- 输入后进入“未保存”，短延迟自动保存。
- 保存中显示非阻塞状态；成功后显示最后保存时间；失败保留本地内容并提供重试。
- 离开未保存内容时拦截并说明选择。
- 用户选中文本后出现局部工具：改写、扩写、缩写、调整人物口吻、提出自定义要求。
- AI 结果以 diff/Revision 出现；主操作是“采用修改”，次操作是“继续调整”，低强调操作是“拒绝”。
- 全量重生成必须说明将创建 Branch，不覆盖当前采用版本。

## Agent Team Activity

Activity 分为四类：

| 类型 | 表现 | 用户动作 |
|---|---|---|
| Task | 成员、目标、进度、上下文 | 查看、取消、重试 |
| Delivery | 新候选或 Revision | 打开、比较、采用 |
| Decision | 等待用户拍板 | 接受、拒绝、编辑后接受 |
| Alert | 错误、冲突或风险 | 定位、修复、忽略并记录理由 |

Activity 不使用模糊的“Agent 正在思考”。必须显示成员名称和具体动作，例如“改编策划师正在把原著第 2–4 章映射为 Story Beat”。长任务显示可取消性和已完成范围。

## 版本与 AI 修改

所有内容状态使用统一词汇：

- **当前采用**：项目正在使用的版本。
- **草稿**：尚未提交比较的用户编辑。
- **候选**：Agent 或用户创建的替代内容。
- **Revision**：可比较的一次修改。
- **Branch**：并行方向。
- **Frozen**：禁止 Agent 修改的上游对象。
- **Dirty**：上游变更后可能失配，尚未确认处理。

“确认”不能作为通用按钮文案。按钮写明结果，例如“采用此方案”“创建分支”“接受 3 处修改”“保持当前版本”。

## 审查与问题处理

审查问题必须包含对象、严重性、证据、建议和处理状态。点击问题定位到正文并高亮相关内容。用户可以接受修订、自己修改、忽略并记录理由，或要求 Agent 提供另一方案。

Ralph Loop 用轮次时间线呈现：每轮显示总分、维度、问题和对应 Revision。分数是辅助证据，不替代问题本身。达到最大轮次时转为 Decision，而不是无限自动重试。

## 改编交互

Adaptation Map 使用“来源 → 决策 → 目标”的映射行。决策包括保留、合并、删除、重排、改写和原创新增。每行显示理由与状态，批量操作只能作用于明确选中的映射。

Scene/Chapter 的 Source Reference 是可点击引用，打开并排来源片段。来源失效时保留旧快照并显示警告，不渲染空引用。

## Growth Tree

Growth Tree 默认只展示当前对象的上下游和主要 Branch，用户主动展开更多节点。选中节点后提供 lineage、descendants、状态和比较入口。树中不塞完整正文、Agent 聊天或阶段进度。

## 状态反馈体系

### 异步状态

- 短操作：按钮内进度和结果。
- 长操作：Activity Task，可离开当前页面继续运行。
- 部分成功：明确成功范围、失败范围和重试入口。
- 失败：保留用户输入，说明原因和下一步，不只显示“失败”。

### 空状态

空状态说明该区域为何为空，并提供唯一的合理起步操作。不得为了填充页面渲染占位卡片或空表格。

### 破坏性操作

项目、正文单位、Source Canon 和 Branch 删除需要确认；优先提供归档或撤销。Character 的数据删除与剧情状态“死亡”是两个完全不同的动作。

## 无障碍与输入

- 所有操作使用 button/link/form control 语义。
- 图标按钮有可访问名称，装饰图标对读屏隐藏。
- 键盘可以完成创建、导航、编辑、比较和决策。
- 焦点使用 `:focus-visible`，不能无替代地移除 outline。
- 异步保存、错误和 Task 完成使用 polite live region。
- 不禁用缩放，不阻止粘贴；表单有 label、name 与 autocomplete 策略。
- 动画尊重 reduced motion，只使用 transform/opacity。

## 响应式边界

V6 桌面优先。宽度不足时先收起右侧协作区，再把左侧目录切换为抽屉；中央编辑器不能被压缩到不可写。移动端只保证阅读、评论和决策，不承诺完整长篇编辑。

## 页面验收模板

每个页面或组件 issue 必须说明：用户目标、入口、主操作、次操作、空状态、加载状态、失败状态、权限/破坏性边界、键盘路径、URL/持久化状态以及至少一个端到端测试。缺少这些内容的 UI issue 不进入开发。
