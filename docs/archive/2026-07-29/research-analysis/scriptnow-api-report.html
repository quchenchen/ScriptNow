ScriptNow API 测试缺陷与性能报告

测试项目：零日（fc6f726c），1卷3章，中文，流程：项目创建→方向→蓝图→StoryMap→写作→采纳

🔴 P0 — 阻塞性缺陷

1. StoryMap 空卷生成：volume_count 未设置时静默失败

当 project.direction 中 volume_one/volume_two 为 null 时，StoryMap 生成成功但 volumes: [] 为空，前端"逐章写作"永久锁定，且无任何错误提示。后端应拒绝生成，或回退到默认参数（1卷3章）。

复现: 创建项目时不传 volume_one/volume_two → 生成 StoryMap → 0卷0章

2. 蓝图采纳 API 409 错误

Blueprint 候选在 state 中可见（2-4个候选），但 POST /blueprints/{id}/adopt 多次返回 409 "candidate is unavailable"。需多次重试或通过前端操作才能采纳。可能原因：候选状态在 generate 和 adopt 之间存在竞态。

复现: generate → 立即 adopt → 409（延迟30秒后有时成功）

3. Cookie 会话频繁过期

access_token 有效期约 10-15 分钟。6个API调用中需要重新登录 4 次。导致批量操作中频繁中断。

影响: 自动化测试/Agent 托管流程不可持续。

🟠 P1 — 性能与可用性

4. API 超时但后台成功（幽灵完成）

蓝图生成和章节生成多次在 curl 180s 超时，但后台实际已完成（候选出现）。客户端被迫轮询 state 端点查找"幽灵"完成的结果。应提供异步任务状态端点（如 GET /tasks/{run_id}）。

数据: 6次生成请求中，3次超时但2次后台完成，成功率 33%（客户端视角）

5. 方向字段类型强制 string

volume_one/volume_two/chapter_target_words 在 direction 中必须为字符串。传数字返回 422。这些值本质上是整数，应接受数值型并自动转换。

复现: {"volume_one":1} → 422； {"volume_one":"1"} → 200

6. 生成过程零可见性

章节生成耗时 2-3 分钟，期间无任何进度信号。客户端不知道是正在处理、排队中、还是已挂死。应考虑 SSE 推送或最小化状态轮询。

7. DeepSeek API 并发争抢

当 Architect（蓝图/StoryMap）和 Writer（章节生成）同时运行时，双方向 DeepSeek API 发送请求。单 Provider 多模型并发数未做限制，可能导致 rate limit 或 queue backlog。

🔵 P2 — 工程与边界情况

8. 项目创建缺少幂等性

多次创建同名项目不做去重。测试期间创建了 "The Last Firewall" 两次（第一次参数错误未删）。

9. 中文内容打包导出曾编码失败

Content-Disposition 头包含中文文件名 → latin-1 编码错误（已修复为 ASCII 文件名 novel-packaged.docx，但仍不支持中文文件名）。

10. 导出功能无进度反馈

15章全文打包约 2s 生成，但无状态返回。对更长文档应考虑异步化。
